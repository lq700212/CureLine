日期：2026-11-02｜状态：**已实施（V0.0.51，方案 C 用户拍板；实施明细见 CHANGELOG V0.0.51）**
配套：布局对比稿见 `docs/UI设计_CIM主窗业务化_对比稿.html`
定位：重构设计 `docs/重构设计_20261028.md` P2 的前置 UI 条目（建议占位 P2.2 前半或新增 P2.3）。

## 1. 背景与问题（为什么要改）

程序② 定位已从老项目"八机通用网关（PLC_ReadDataA）"演进为 **CIM 整线过账网关**
（6 MES 接口 × 8 机台，触发→组包→POST→回写 STATUS），但主窗内容区仍是 Form1
的 1:1 复刻形态：**8 张卡片 = 机台名 + 心跳灯 + 日志 ListBox**（`StationPanel.xaml`）。

错位诊断（四条）：

| # | 错位 | 现状证据 |
| --- | --- | --- |
| 1 | 展示"通讯在不在"，不展示"账过没过成"——6 接口在主窗零可视化 | 卡片只有心跳灯 + 日志文本流 |
| 2 | 卡片日志与 `MesLogWindow`（分机台日志窗）功能重复 | `StationPanelViewModel.LogLines` 上限 100 条，单击全文弹 MsgBox 还是老项目语义 |
| 3 | 无整线维度：在线 N/8、今日触发/成功/失败、MES 端点连通——程序①反而有（顶栏过账状态+工单带） | `MainWindowViewModel` 无任何统计状态 |
| 4 | 老项目残留：缺省机台名=老产线 8 台设备（`AppConfig.DefaultStationNames`）；扫描周期只显示 0 号机实测（`StationGateway.Loop` 只 `id==0` 上报） | `docs/images/gw-main.png` |

**数据层根因**：`StationGateway` 只有日志文本事件（`StationLog`），**没有结构化的
接口级结果通道**——`HandleApi` 的成功/NG/失败三出口都只发字符串。UI 想统计必须
先在 Core 加"观测"事件（见 §3）。

## 2. 目标与非目标

**目标**：主窗一眼回答三件事——① 整线过账健康度（汇总条）；② 每台机台 6 接口
各自过成情况（卡片）；③ 出问题时一键到日志/报警对账（既有窗保留）。

**非目标（红线，本次零改动）**：
- 触发→组包→POST→回写业务链、STATUS=2/MSG=NG、DATA 拆包无补零、分帧
  125/123、失败不重传、一次扫描只处理一个触发（`MultiMachineGateway.cs` 全部协议语义）；
- 触发字轮询一次只处理一个触发（`PollTriggers` 原样）；
- 顶栏/设置下拉/双主题/无边框壳、视图筛选下拉（Form2/Form6 合并成果）；
- 门禁口径（网关设置 dev 可见、调试/日志不设门槛）。

## 3. 设计条目（S1~S6）

### S1 整线汇总条（筛选条升级）★推荐标配

- 现筛选条（视图下拉 + 扫描周期）扩为：**视图下拉 | 在线 N/M | 今日触发 x·成功 y·失败 z | MES 端点+最近报文状态点 | 扫描周期**。
- 在线 N/M：M=启用机台数（`StationUse`），N=在线数（Heartbeat/StationBroken 累计，事件已有）。
- 今日触发/成功/失败：来自 §4 新事件 `ApiDone`，进程内累计、**重启清零**（观测数据
  不落盘，对账以 MES 日志窗/日志文件为准——避免第二本账）。
- MES 端点状态点：**只反映最近一次报文结果**（成功绿/失败红/从未触发灰），不做
  心跳 ping——无触发时的"连通"是假象，不做。
- 配置键：**零新增**。

### S2 卡片业务化 ★核心条目

卡片结构（自上而下）：

1. 头行：机台名 + 心跳灯（既有）+ 今日徽标"触发/成功/失败"三数；
2. **6 接口状态微表**（核心增量）：每接口一行——接口码 | 语义短名 | 触发数 |
   成功数 | 失败数 | 最后结果点（绿=STATUS=1 / 红=NG或失败 / 灰=未触发）；
3. 底部**最新消息一行**：溢出省略 + 悬停 ToolTip 全文 + 点击开分机台日志窗。

- 卡片 ListBox **移除**（与日志窗重复的部分收敛进日志窗，信息不丢失）。
- 语义短名（静态映射，与客户手册 §3 同源）：0027 固化时间 / 0028 报警异常 /
  0030 进出站 / 0031 物料绑定 / 0032 物料上传 / 0033 测试记录。
- 颜色一律走主题语义键（`Brush.State*` 既有键，勿硬编码）。

### S3 单机视图增强（视图筛选选单台时，可后置）

- 单机模式布局：左=接口明细大表（追加最后 STATUS/MSG 文本、最后触发时间、
  最近报文耗时）；右=最近触发流（即现卡片日志内容的新家）。
- 与 S2 是同一数据源的两个视图，无新事件。

### S4 缺省机台名中性化 ★小改先行

- `AppConfig.DefaultStationNames` 从老产线 8 设备名改 **"机台1"…"机台8"**；
- `[StationNames]` 配置化键**不变**（V0.0.32 已做），D/R 定版后现场填真名；
- 同步：`config.sample.ini` 注释、主窗/文档截图（gw-main.png 等）、相关测试断言。

### S5 扫描周期口径

- 现状"只 0 号机实测"（老项目口径）语义含糊——改：**汇总条显示配置值**
  （`[setting] ScanIntervalMs`），**单机视图显示该台实测值**（`ScanElapsed` 扩为
  每台都报，或按 id 存字典）。

### S6 0028 存图链去留（**挂起决策，待 W68 终版**）

- 现链：卡片日志行含"存图上报+图片路径"时单击开图（`ShowStationDetail` →
  `ImageWindow`）。卡片 ListBox 移除后此链入口只剩日志窗。
- 拍板点：W68 终版若整线保留 0028 存图 → 日志窗补"点击含图行开图"；
  若不用 → 整链删（`ShowStationDetail` 存图分支 + `ImageWindow`/`ImageViewModel`）。
- 在此之前**代码不动**，避免做了再拆。

## 4. 数据通道（Core 唯一新增，"观测"不动协议）

```csharp
// StationGateway 新增（MultiMachineGateway.cs）：
// HandleApi 三出口（成功/NG/WriteFail）各发一次；PollTriggers 命中触发即发 Triggered。
public event Action<int, string, bool, string, string, long>? ApiDone;   // id, apiCode, ok, status, msg, 耗时ms
public event Action<int, string>? ApiTriggered;                          // id, apiCode
// MultiMachineManager 同名透传（与既有 Heartbeat 等事件同款写法）。
```

- 三出口对照：成功（status=="1"→ok=true）/ MES返回NG（ok=false,status=返回值）/
  WriteFail（ok=false,status="2"）——**只在既有分支末尾追加发事件，不改任何回写**。
- UI 侧：`StationPanelViewModel` 加 6 行接口状态模型（`ApiStatRow`）；
  `MainWindowViewModel` 加整线累计（S1）。
- 均后台线程触发（铁律 2），UI 订阅处 `UiInvoke` 封送（与现有事件同款）。
