## 1. 背景与目标

现场 IO 方案确定为 **IO 耦合器**（Modbus TCP 从站），不再经 PLC 直读触发。据此用户拍板四件事：

1. 本地库 kaleidoscope 升到最新并以 git submodule 接入（已完成：85811e9 → f53d14b V1.8.2）。
2. 通讯全部换成 IO 耦合器读取触发；点表配置做到"点点鼠标"级别，现场人员不改代码。
3. 业务拆成**两个独立 exe**（可部署不同工控机）：
   - **程序①固化程控**：IO 耦合器程控（仓位计时/放行/三色灯）+ 单线过账 —— 新建 `CureStation`；
   - **程序② CIM 整线过账**：6 个 MES 接口 + 整线联调 —— 现有 PlcMesBridge 主程序演化（目标命名 CimGateway）。
4. 客户两张 HMI 参考图（权限管理 + 工单信息）看懂并落实（Phase 3）。

业务口径（引用自报价文档 §1，金额见内部件不在此复述）：

* A 线 OP30 独立一台管 A 线，B/C 共用一台；本项目**纯上位机**——读 X 状态（光栅/托盘）+ 计时放行 + 写 Y 三色灯 + D 区握手，**不做 PLC 程序、不做电气施工**。
* 程控 = 计时为主（即使有气缸逻辑也简单，报 §6.1 加价点登记，不脑补）。
* 整线过账 = 6 MES 接口（W68 终版待客户）+ 整线联调。

## 4. 点表布局（IO 表落死，改这里必须同步测 `PointTableTests`）

> **V0.0.41 现场口径（现行）**：一台机台 = 10 列 × 上中下 3 层 = 30 仓位，
> **每列 1 台町洋 NEMO GFNB-1A3A**（1 块 = 16DI+16DO），即 **10 台设备各管
> 一架 3 层**，IP 现场现值 192.168.1.20~.29 已预置缺省模板
> （`BuildMachineTemplate`：自愈 + 配置窗批量生成共用；GFNB 寄存器占位
> DI@0x1000/DO@0x2000 对照官方手册 6.4/6.5 节核实一致）。下文 4.1/4.2 的
> "单台 10 块"是 Audi IO 表时代的布局假设，仍作单台模板能力保留
> （`BuildDefaultTemplate`），现场走多台口径。

来源：`docs/副本苏州毅嘉Audi cover module_电气硬件设计IO表_20260921.xlsx` A-OP30 页——10 块 GFNB-1A3A 扩展，10 架 × 3 层 = 30 仓位，有效 90DI（光栅/托盘）+ 90DO（三色灯）。

### 4.1 地址布局

每块占 **0x20 = 32 个寄存器地址**：16 DI（占 0x10）+ 16 DO（占 0x10）。块号 K 从 1 起：

| 寄存器 | 地址公式 | 缺省（K=1） | 例（K=7） |
|---|---|---|---|
| DI（FC04 读） | `DiStartAddress + (K-1)×0x20` | 0x1000 | 0x10C0 |
| DO（FC03 读 / FC06 写，单寄存器） | `DoStartAddress + (K-1)×0x20`（= DI + 0x10） | 0x1010 | 0x10D0 |

三种可配：`DiStartAddress` / `DoStartAddress` / `BlockStrideRegisters` —— 现场布局与假设不符时改 JSON 三键即可，代码零改。

### 4.2 位布局（块内）

每 4 位一组 = 1 层（层1=bit0~3、层2=bit4~7、层3=bit8~11、layer4 或余量=bit12~15）：

| 组内 bit | 输入（DI） | 输出（DO） |
|---|---|---|
| 0 | 左光栅 OK（RackLightL） | 状态灯_红（LampRed） |
| 1 | 右光栅 OK（RackLightR） | 状态灯_黄（LampYellow） |
| 2 | 托盘有无（TrayDetect） | 状态灯_绿（LampGreen） |
| 3 | 预留 | 预留 |

模拟 & 取反开关：`InvertInputs` / `InvertOutputs`（现场线路低有效时勾选，bit=0 视为 ON）。

### 4.3 语义键与校验

* 业务代码只认 `IoPointKey(IsInput, Role, Rack, Level)`，地址换算收敛在 `IoCouplerDevice.DiAddressOf/DoAddressOf` 一处。
* **重复绑定两道闸**（`PointTableValidator`，保存前必跑）：
  1. 物理唯一：同一（方向+块+位）只能一行；
  2. 语义唯一：同一（方向+角色+架+层）只能绑一个物理点（快照按键建字典，两行同键会让状态机取到二义值）。
  另有范围闸：块号 ∈[1,BlockCount]、bit∈[0,点数-1]、角色与方向匹配、架 1~99、层 1~3、Reserved 行仓位必须清零。
* 校验不过不落盘、不启动，界面给出全部错误行。

### 4.4 缺省模板与自愈

* `BuildDefaultTemplate(名称, IP, 架数, 层数)`：层数 ≥5 报错（每架只占 4 位；更多层拆设备）。生成**全物理点绑定**：10 块 × 16 点 × 2 方向 = 320 行，其中业务点 60 行（10 架 × 3 层 × 6 点）+ 预留 260 行（`FunctionName` 空、可后配）。
* `Load`：文件不存在 / 空 / JSON 损坏一律回 null + 原因进日志（启动期不弹框），启动流程自动 `BuildDefaultTemplate(... 10, 3)` 兜底**并落盘**——现场第一次开机就有东西看。

## 5. 通讯底座（IPointTableBus）

| 成员 | 语义 |
|---|---|
| `Start(config)` | 校验由调用方先跑；建连失败不算失败（后台自愈重连） |
| `LatestSnapshot` | 最新快照（不可变引用，读侧原子取） |
| `PointChanged` / `ConnectionChanged` / `Error` | 后台线程触发；UI 订阅方必须封送（铁律 2） |
| `WritePoint(key, state)` | 写 DO。返回 false = 未绑定/通讯失败，不抛 |

**真机 `ModbusPointTableBus`**：

* 单线程串行扫全部设备——耦合器单连接，并发多线程反而抢同一 TCP；每周期每台按 **(方向, 块) 分组共用一帧**（V0.0.41 由"逐绑定一帧"去重为"逐块一帧"，`ScanPlanner.BuildScanPlan` 纯函数：FC04 读 DI 1 寄存器 + FC03 读 DO 1 寄存器，组内逐位取值；10 台 × 每台 1 块 = **20 帧/周期**），周期取全场最小 `PollIntervalMs`（缺省 250ms）。
* **为什么不用 kaleidoscope 的连续 `ReadAllInputs`**：块状布局地址不连续（32 地址只用到 16 位），连续读会把错位数据当真——故子模块新增原始方法 `ReadInputRegisters(ushort addr, ushort count)`（FC04 任意地址，与 `ReadHoldingRegisters` 对称；**该改动已编译验证，尚未 commit/push，见 §8**）。
* **DO 写 = 读-改-写（RMW）单寄存器位**：绝不能整寄存器覆盖——同寄存器里还有别的仓位的三色灯（kaleidoscope 红线）。
* 重连：轮询前发现未连接 → 5 秒节流重连（铁律 3 口径的重连节流本身：`MelsecPlcClient` 是 5s 节流，本处同款做法）；失败只 Error 一次边沿，不刷屏（铁律 4）。半失败（部分帧失败）整轮丢弃，不算 connected。
* 状态差分：同一拍只对**变化点**发 `PointChanged` 边沿。

**演示 `MockPointTableBus`**：

* 托盘/光栅按仓位顺序流转（托盘到 → 左右光栅亮 → 保持 → 下一仓位）；DO 由状态机写入直接入快照，演示"写生效"。
* 周期性演示掉线→重连（黄牌演示，细节见 `MockPointTableBus` 注释）；有配置才演示掉线。
* 开关沿用 `config.ini [setting] Simulate=1`（与主程序同名键，跨程序一致的运维习惯）。

**连通测试 `IoCouplerConnectionTester`**：三态文案——连不上（超时网线/IP）/连上但读不通（起始地址或功能码不符，指路 Modbus Poll 校准）/OK（回显读到的 DI/DO 原始值）。测试专用连接测完即断，不留半开会话。

## 6. CureStation 现状（P1 骨架 + P3.1 状态机/工艺策略）

* **主窗**：30 仓位卡片网格（10×3 最小下限铺满，点表更大则跟随扩展），每卡显示 托盘/光栅/灯/仓位状态（状态机口径：空闲/待门控/计时中 剩X分/放行；空闲仓位走灯色反推口径）；顶栏连接状态 + 当前策略 + 重连 + 工艺策略/点表配置入口。
* **登录与四级权限（P3.2 前半）**：顶栏"登录"进四级操作员（L1 操作员/L2 班长/L3 工程师/L4 管理员，`Security/OperatorStore` operators 表 + PBKDF2 复用 PasswordHasher）；主窗 `Gate(级别, 功能)` 统一门禁——工单 L1+、工艺策略 L3+、点表/权限管理 L4+，未登录一律拦下；防锁死红线（最后一个 L4 删/降拒绝）在 Store 层。
* **工单信息窗（P3.2 前半，对照参考 HMI"工单信息"页）**：R/L 双工位各 { 途程单号 RC_NO/预设数量/已生产数量 } + 计数清零 + 员工工号 EMP_NO + 物料条码 BC_NO + 制程代码 PT_NO×2 + 物料上传使能（存储位已落，动作接线在过账轮）；存 `config/workorder.json`（`Curing/WorkOrderStore`，运行时数据，字段名对齐 MesParamStore 16 字段，过账直接映射）；窗内编辑区按级别细分禁用（途程/数量 L2+、制程 L3+、员工工号/条码 L1+），Flush 门禁兜底回原值防越权。
* **仓位状态机（P3.1，`Core/Curing/SlotCuringMachine`）**：托盘到位 →（门控开则等光栅让空）→ 黄灯计时 → 到点绿灯放行 → 托盘离开灭灯回空闲；任何时刻托盘离开都回空闲（计时中取件记日志）。灯写/计时全在后台线程（边沿由主窗 VM 后台直转 + 内部 1s 心跳 Pump，铁律 2）；灯写"期望 vs 已写"去重比对（稳态零网络写，失败下轮补写）；断连恢复 `AlignFromSnapshot` 托盘在架重新计时；策略热切换不影响进行中的仓位（按开计时那一刻锁定时长走完）。**断电续算可配置（P3.1 补丁）**：策略勾 `PersistMinutes` 后进行中仓位随状态变化落盘 `config/curingstate.json`（`CuringStateStore`，运行时数据非配置），重启按记录续算（断电时间计入固化时长）；缺省关=重计口径，删状态文件即回退重计。
* **工艺策略窗（P3.1，参考 AgingTestSystem 配方管理模式）**：策略库增删选 + 编辑（名称/全局时长/光栅门控/每层覆盖 4 框/每仓位覆盖行表）+ 激活并生效/仅保存（先校验后落盘，错弹框不写文件）。时长**三级覆盖**：仓位 > 层 > 全局（`ResolveMinutes` 一处收敛），三种粒度可混用；光栅门控开=左右光栅都灭且托盘在架才开计时（没绑光栅自动放行）。
* **单线过账（P3.2 后半，全配置化）**：`Curing/CuringMesOptions`（ini `[CuringMes]` 节：开关/工位/时间单位/进站时机/中途取件/静态参数五件）+ `Curing/CuringMesPoster`（状态机边沿→MES 报文）。触发映射=老项目 PLC_ReadData 命令字：托盘到位=进站（API0030 I）、托盘离开=出站链（先 API0027 固化时间外层数组后 API0030 O）、出站被接受（STATUS=1）→对应工位已生产+1；工单窗 R/L 上传按钮=API0032 物料上传（先保存工单再提交，按按钮工位取槽）。发送门槛双保险（总开关+URL 非空）；失败只记日志+顶栏状态（不弹窗不重传）；四入口全 Task.Run 后台+异常兜底；`UpdateOptions` 热更新（配置窗保存即生效）。**过账配置窗（L4）**一窗全改（含三接口 URL，与主程序 [MES] 同键），右列口径说明。状态机挂三事件（TrayArrived/CuringStarted/TrayLeft）只发真实边沿（重启对齐不发，防重复过账）；事件在 _sync 锁内触发，处理器禁止同步回调状态机（红线）。BC_NO=工单批次物料条码（批次级过账；板级走程序②，架构差异已登记）。
* **刷新策略**：UI 仍 500ms `DispatcherTimer` 拉快照+状态机状态全量刷（风险 4 对策落地：状态机走边沿+心跳在后台，500ms 全量刷只是 UI 兜底，不另起线程）。
* **点表配置窗**（点点鼠标核心）：设备列表增删 + 设备编辑（名称/IP）+ **一键缺省模板**（架数×层数生成全套绑定）+ 绑定行增删改（块/位/方向/角色/架/层/功能名，点下拉选中-role）+ **测试连接**（后台 Task 不冻界面）+ **保存**（先校验后落盘，错弹框不写文件）。
* **自愈**：点表缺 → 缺省模板落盘提示；点表坏 → 校验错误全列 + "点表有误（见点表配置窗）"，模拟模式兜底照样启动；策略库缺/坏 → 缺省库（"标准固化"120 分钟，现场工艺时长确认后策略窗改）静默落盘。
* **MVVM 纪律**：全窗 `d:DataContext` + 展示文本/Visibility/数值 `FallbackValue`（AGENTS XAML 设计时纪律）；VM 不碰 Window/MessageBox，全走 `IDialogService`;节拍内状态更新经 `ViewModelBase.UiInvoke` 封送。
