# 整线网关 客户技术工艺手册

> 适用版本：整线网关（CimGateway）V0.0.22 及以后
> 适用对象：客户工艺/设备工程师（联调与报文对账方法）
> 截图说明：截图均为演示模式数据；报文示例取自演示触发，字段以
> 现场对接文档为准。

---

## 1. 本手册讲什么

对接 MES 时工程师最关心的三件事：

1. **数据链路**：报文从哪来、到哪去，谁组包谁收单；
2. **接口清单与字段落位**：六个 MES 接口各自发什么、字段怎么填；
3. **联调工具**：调试窗手动发报、日志窗对账、报警窗判错。

部署与账号管理不在本手册（见交付清单/内部手册对接人）。

## 2. 一条报文的旅程

```
[设备] 触发（以太网，逐台独立）
   ↓
[整线网关] 读寄存器 → 按接口组包 JSON
   ↓
[整线网关] → HTTP POST → MES 接口地址
   ↓
[MES] 返回结果（STATUS=1 成功 / 非 1 拒绝）
   ↓
[整线网关] 把结果回写设备对应寄存器（COUNT/MSG/DATA 等）
      ├ 成功 → 设备继续
      └ 失败 → 回写 STATUS=2/错误 MSG + 弹报警窗 + 记日志窗
```

- 组包与拆包**全部在软件自动完成**，设备侧不感知 HTTP；
- **失败不重传**：状态回写给设备，由现场作业侧决定是否重触发
  ——防止 MES 侧重复记账（报警窗会给出理由）。

## 3. 六接口清单

软件对接的 MES 接口共 6 个，按序号对应：

| 接口 | 中文语义 | 报文外层 | 关键字段数 | 典型触发 |
| --- | --- | --- | --- | --- |
| API0027 | 生产参数/固化时间上传 | 数组 `[]` | 8 | 计时完成 |
| API0028 | 报警/异常上传 | 数组 `[]` | 7 | 设备报警位 |
| API0030 | 进出站 | 对象 `{}` | 11 | 进站/出站触发 |
| API0031 | 物料绑定 | 对象 `{}` | 8 | 扫码绑定 |
| API0032 | 物料上传 | 对象 `{}` | 8 | 物料动作 |
| API0033 | 测试记录 | 数组 `[]` | 16 | 测试完成触发 |

> 报文外层形状（数组/对象）是 MES 侧文档约定，组包由软件按序号
> 自动区别，**请勿在 MES 侧改动这一口径**。

**触发与扫描**：软件按配置的扫描周期轮询各机台的触发字（真机上电
自动跑）——**一个触发一次报文**，不存在只报一次后"手动"追加。

## 4. 字段落位：16 记忆字段 + 每接口取用表

六个接口的字段全部来自**软件打包时的参数记忆**（16 个），
在调试窗可预填（见第 6 节）。全量字段表：

| 字段名 | 中文说明 | 备注 |
| --- | --- | --- |
| RC_NO | 途程单号 | 必改现场值（每批不同） |
| PT_NO | 制程代码 | 按客户 MES 工艺路径登记 |
| MAC_NO | 机台编号 | MES 侧设备档案号 |
| MAC_LOC_NO | 机台位置号 | MES 侧位置编号 |
| PLANT | 厂别 | 一般固定 |
| PRA_CODE | 参数/状态编码 | 对应 PRA 类别 |
| PRA_Value | 参数/状态值 | 0027/0028 的时间/值 |
| Collect_Datetime | 采集时间 | 0027 专用时间戳 |
| ACTION | 进出标志(I/O) | 0030 专用：I=进站 O=出站 |
| BC_NO | 条码 | 批次/板级条码按接口 |
| SP_MEMO | 员工工号(SP) | 0030 专用 |
| EMP_NO | 员工工号(EMP) | 0031/0032 专用 |
| TL_EL_NO | 工具号 | 0030 专用 |
| IN_DATETIME | 进出/上传时间 | 0030/0032 专用 |
| CHECK_RESULT | 检测结果(0/1) | 0030 专用 |
| BO_NUMBER | 板号(LINK) | 0031 专用 |

**各接口实际取用与报文形状**（接口字段打包按下表）：

| 接口 | 请求体形状 | 取用字段 |
| --- | --- | --- |
| API0027 | 外层数组 [ {8 字段} ] | RC_NO, PT_NO, MAC_NO, MAC_LOC_NO, PRA_CODE, PRA_Value, Collect_Datetime, PLANT |
| API0028 | 外层数组 [ {7 字段} ] | RC_NO, PT_NO, MAC_NO, MAC_LOC_NO, PRA_CODE, PRA_Value, PLANT |
| API0030 | 单个对象 {11 字段} | RC_NO, ACTION, BC_NO, PT_NO, SP_MEMO, MAC_NO, MAC_LOC_NO, TL_EL_NO, IN_DATETIME, CHECK_RESULT, PLANT |
| API0031 | 单个对象 {8 字段} | RC_NO, BC_NO, PT_NO, EMP_NO, MAC_NO, MAC_LOC_NO, BO_NUMBER, PLANT |
| API0032 | 单个对象 {8 字段} | RC_NO, BC_NO, PT_NO, EMP_NO, MAC_NO, MAC_LOC_NO, IN_DATETIME, PLANT |
| API0033 | 外层数组 [ {16 字段} ] | RC_NO, BOARD_SN, TOP_BTM, LINE_NO, PT_NO, S_TEST_TIME, E_TEST_TIME, CHK_STATUS, DOT_LOC, BIN_LOC, IMG_LOC, ERR_NO, SCR_ACTUAL, SCR_STD, SCR_MAX, PLANT |

> **API0033 专有 11 字段**（BOARD_SN/TOP_BTM/LINE_NO/S_TEST_TIME/
> E_TEST_TIME/CHK_STATUS/DOT_LOC/BIN_LOC/IMG_LOC/ERR_NO/
> SCR_ACTUAL/SCR_STD/SCR_MAX——测试明细数据）不进参数记忆，只在
> 调试窗或真实触发时填。

**字段值来源**：多数由设备触发时从机台寄存器读出后打包——只有
PLANT 之类少数固定值在**配置**里维护；现场对**字段清单**如有补充，
联系实施工程师走配置，不要手改报文格式。

  登录 / 当前时间；

## 6. 调试窗联调（手动发一条验证全链路）

菜单 **MES 接口调试界面**：

![MES 接口调试窗](images/gw-debug.png)

**联调四步**（不用等设备真触发）：

1. **接口类型**：选要试的接口；
2. **填字段**：页面给 9 行常用字段框（含示例值），改完报文预览区
   立即刷新——**预览即真实报文**（JSON）；
3. 点 **手动上传到MES**；
4. 看 **MES 返回信息**区：返回原文原样贴出，对账即以这里为准。

两个按钮的差别：

| 按钮 | 干什么 |
| --- | --- |
| 保存参数到本地 | 把字段值存盘（下次打开默认带出，联调试样用） |
| 手动上传到MES | 按当前字段立即发一条 |

**联调注意**：

- 手动上传的报文**与真实触发走同一条链路**，返回也一致——对账联调
  用它完全等价；
- **字段填充有规则**：如 BC_NO 类型、时间戳格式（对齐 MES 接受的
  文本口径），对接文档在哪里、报文里就怎么填；
- 演示模式下设备侧不会真跑，**照样可联调**（这是验证 MES 侧接口
  最省事的方法）。

## 7. 日志窗对账（真实触发的报文原文）

顶栏【日志】按钮：

![MES 交互实时日志窗](images/gw-log.png)

- **每条报文都有原文**：请求 JSON、返回结果、时间戳；
- 视图支持按机台分栏（单机台中不混流）；
- 对账做法：把日志窗里"请求 JSON"逐字段与第 4 节字段落位表对照，
  MES 侧把返回 JSON 逐字核对；
- 窗口右下角 **清空当前显示** 长滚动时用。

---

## 8. 报警链（失败时三处都有记录）

上传失败/被拒时**三处联动**：

1. **设备**：回写失败状态与 MSG（设备侧面板/看板可见）；
2. **报警窗**（自动弹出）：

   
   行文例：`上传失败: API0028 返回非 1（STATUS=2, MSG=设备号不存在）`——
   接口名 + 返回码 + MES 原因**三项在一个窗口**，截图即可对账；

3. **日志窗**：同样报文有原文件档。

**失败重试原则**（同第 2 节）：软件**不自动重传**——由现场作业侧
根据报警原因处理后再触发，避免 MES 记账重复。

顶栏【修改密码】按钮：

  实施工程师在交付时统一建好。

## 10. FAQ

**Q1：联调时报文发出去了，MES 一直没响应？**
先看返回信息区是否超时——超时多为网络/URL 未对齐；有响应是
STATUS=2 之类，是 MES 侧对字段/参数的拒绝（按返回errMsg对齐）。

**Q2：改字段值影响真触发吗？**
不影响。调试窗字段是**联调专用**的临时值；真触发时字段重新从
设备读出，与你手动改的值无关。

**Q3：怎么确认当前机器的编号（MAC_NO）在 MES 有登记？**
直接调 API0030 一条：返回 STATUS=2 且 MSG 提"设备号不存在"就是
未登记——MES 侧建档即通。

**Q4：视图筛选成"单机台"后另一台的日志还进吗？**
进。日志窗记录全部机台报文，视图只是显示过滤，不建议长期单开
（对账需要全景时切回全部）。

**Q5：AMES 时间戳格式不一致？**
采集时间格式（Collect_Datetime）与接口约定统一定义于软件——
报文里以原文为准；MES 侧重格式的话由实施工程师走配置调整。
